# 小说 IP 国风动漫生产系统规划

版本：1.0  
状态：APPROVED_FOR_IMPLEMENTATION  
定位：以小说或古典文学 IP 为源头，持续生产角色一致、剧情连续、可人工审核的竖屏国风动漫剧集。

## 1. 重新定义产品

系统不再以“一条 60 秒知识视频”为中心，而以“一个可以持续更新的动漫剧集项目”为中心。

核心对象层级：

```text
IP
└── 底本 / 授权与版本
    └── 剧集 Series
        └── 季 Season
            └── 故事弧 Arc
                └── 集 Episode
                    └── 场 Scene
                        └── 镜头 Shot
                            └── 素材 Asset / 渲染 Render
```

正式工作流：

```text
IP 与底本准入
→ 原文解析与故事知识库
→ 世界观 / 角色 / 时间线圣经
→ 全剧与季度改编规划
→ 单集剧本与节拍
→ 场景和逐镜分镜
→ 角色 / 场景 / 道具资产
→ 分镜样片
→ 配音 / 音乐 / 音效
→ 动态镜头生成
→ 剪辑 / 合成 / 字幕
→ 连续性与技术质检
→ 人工审核
→ 发布包
→ 数据回流
```

现有《镜花缘》五集属于 `ANIMATIC_PROTOTYPE`，用于验证本地链路；它不是正式剧集母版，也不作为新流程的数据模型样板直接扩展。

## 2. 当前系统缺口

| 领域 | 已有能力 | 关键缺口 |
|---|---|---|
| IP | 候选池、初步权利门 | 指定底本、授权地域、可改编范围、引用定位与发布门联动 |
| 剧情 | 单集改编试点 | 全剧梗概、季度主线、故事弧、伏笔回收、角色成长弧 |
| 连续性 | 简单场景脚本 | 世界规则、人物关系、服装状态、伤势、道具、地点与时间线记忆 |
| 角色 | 单张设定板 | 角色圣经、转面、表情、服装版本、声线、禁改特征和身份一致性检查 |
| 视觉 | 三张关键帧 | 视觉圣经、色彩脚本、场景库、道具库、构图模板、参考图包版本 |
| 镜头 | 本地推镜、远程 Provider | 镜头级动作意图、首尾帧、镜头连续关系、失败回退和局部重做 |
| 音频 | TTS、字幕 | 角色选角、逐句表演参数、多人对白、旁白、音乐、音效和混音 |
| 剪辑 | FFmpeg、EDL | 集级时间线、声画节奏、镜头替换、对白对齐、口型与最终调色 |
| QC | 技术/内容/视觉 QC | 角色一致性、剧情矛盾、台词归属、服装道具连续性、镜头可读性 |
| Web | 项目与 Provider 页面 | IP 工作区、编剧室、角色库、分镜台、资产库、音频台、渲染队列和审核台 |
| 数据 | JSON 阶段产物 | 稳定 ID、Schema 版本、依赖关系、资产血缘、成本账本和变更影响分析 |

## 3. 系统分层

系统由五个横向基础能力支撑：

```text
领域模型：IP、故事、剧集、镜头、资产、审核
存储层：SQLite 元数据 + 文件系统媒体；通过 Repository 接口允许未来迁移 PostgreSQL / 对象存储
任务层：持久化作业队列、重试、取消、并发锁、进度和恢复
Provider 层：LLM、图像、视频、口型、TTS、音乐、ASR 的可替换 Adapter
审计层：版本、输入输出血缘、成本、人工操作、密钥来源和发布记录
```

本地单用户版本不引入分布式基础设施。SQLite 保存可查询状态，JSON 作为可导出和可审阅的领域快照，图片、音频、视频继续保存在项目媒体目录。数据库不是唯一真相：每个通过审核的里程碑都导出带 Schema 版本的 manifest，支持备份、迁移和恢复。

### 3.1 IP 与来源层

职责：记录作品、作者、底本、章节、来源、授权、目标地区、改编限制和人工审查结论。

核心产物：

```text
ip.json
source-editions.json
rights.json
source-index.json
adaptation-policy.json
```

每个剧本节拍必须能指向原文章节或明确标记为原创增补。权利状态影响发布，不阻止本地技术试验，但所有技术试验必须带 `publication_allowed=false`。

### 3.2 故事知识与连续性层

职责：把原文变成可查询、可校验的长期故事记忆。

核心产物：

```text
story-bible/world.json
story-bible/characters/*.json
story-bible/relationships.json
story-bible/locations.json
story-bible/props.json
story-bible/timeline.json
story-bible/rules.json
story-bible/continuity-ledger.json
```

连续性账本记录每集结束时的角色位置、服装、携带物、伤势、已知信息、关系变化和未回收伏笔。下一集开写前必须加载上一集结束状态。

### 3.3 改编与编剧层

采用四级规划：

```text
全剧规划：主题、终局、主要角色弧、允许改编边界
季度规划：季度目标、核心冲突、阶段高潮、季终钩子
故事弧规划：3～8 集的局部目标、升级与回收
单集规划：Hook、目标、阻碍、转折、高潮、结尾钩子
```

单集剧本必须区分：动作、对白、旁白、情绪、声效、画面信息和原文映射。任何影响后续连续性的改变都写入 continuity delta。

核心产物：

```text
series-plan.json
seasons/S01/season-plan.json
seasons/S01/arcs/*.json
episodes/E001/episode-outline.json
episodes/E001/script.json
episodes/E001/continuity-delta.json
```

### 3.4 视觉开发层

职责：建立长期复用的美术规则，避免每集重新抽卡。

核心产物：

```text
visual-bible/style.json
visual-bible/color-script.json
visual-bible/composition-rules.json
assets/characters/<character-id>/
assets/locations/<location-id>/
assets/props/<prop-id>/
```

角色资产至少包括：正侧背转面、近景头像、基础表情、关键服装、身高比例、固定配色、发型和饰品细节、负面约束、语音角色 ID。场景资产记录时间、天气、光线和可复用机位。

### 3.5 镜头与分镜层

每个镜头具有稳定 ID，例如 `S01E001-SC003-SH002`。

镜头记录：

```text
叙事目的
场景与角色状态
景别 / 机位 / 镜头运动
动作起点与终点
对白或旁白
首帧 / 尾帧参考
角色、服装、场景和道具引用
生成策略与 Provider
预算、尝试次数、选中版本
前后镜头连续性约束
```

先生成静态 storyboard，再生成带时长的 animatic。剧本和节奏未通过审核前，不允许批量调用收费动作模型。

### 3.6 音频层

音频拆成独立轨道：

```text
旁白
角色对白
环境声
动作音效
音乐
```

每个角色拥有 voice profile；每句对白记录说话人、情绪、速度、音高意图、停顿和发音覆盖。系统先以本地 TTS 做节奏样片，通过后再允许替换为收费声线。音乐必须记录来源与使用许可。

### 3.7 动态生成与渲染层

镜头级路由：

```text
local_animatic       静态关键帧 + 推拉摇移 + 转场
image_to_video       角色或场景参考图生成动作
keyframe_to_video    首尾帧控制
lip_sync             对白特写口型
template_motion      字卡、地图、转场和特效
manual_import        人工动画或外部成片
```

所有远程能力继续通过 Provider Adapter 接入。镜头渲染结果保留提示词、模型、参数、参考图版本、成本、时间和失败原因。失败只能重做当前镜头，不重跑整集。

### 3.8 剪辑、QC 与审核层

新增六类质量门：

1. 来源与权利门：底本、授权、引用和发布范围。
2. 剧情门：因果、人物动机、节奏、钩子和伏笔。
3. 连续性门：人物外观、服装、位置、道具、伤势、知识状态和时间线。
4. 视听门：角色身份、动作可读性、字幕、对白、音效和音乐。
5. 技术门：分辨率、帧率、编码、响度、黑帧、冻结帧和声画同步。
6. 人工发布门：成片、标题、封面、声明和平台设置最终确认。

自动修复仅处理字幕位置、音量、转码和轻微时长等机械问题；剧情、角色、台词含义和权利结论必须人工决定。

### 3.9 发布与反馈层

一份母版生成不同平台的派生版本，记录裁切、字幕安全区、封面、标题、简介、话题、版权声明和导出校验和。正式发布仍由人工完成，系统只记录发布时间、平台作品 ID 和人工确认人。

发布后的播放、完播、互动、关注转化和负反馈进入集级分析；数据用于比较钩子、时长、角色和故事弧，不直接改写剧情或自动发布下一集。

## 4. 稳定 ID 与数据血缘

建议 ID：

```text
IP-JHY
SER-JHY-01
S01
ARC01
E001
S01E001-SC001
S01E001-SC001-SH001
CHR-TXS
LOC-SEA-CABIN
PROP-BROKEN-MAP
AST-...
RND-...
```

每个产物必须包含：

```text
schema_version
id
project_id
revision
status
created_at / updated_at
input_refs
source_refs
provider
human_review
```

产物之间以 ID 引用，不以临时文件名暗示关系。更新角色服装或剧本时，系统可以计算受影响的集、场、镜头、配音和渲染，生成局部重做计划。

## 5. 状态机与审核门

```text
DRAFT
→ SOURCE_READY
→ BIBLE_READY
→ WRITING_READY
→ STORYBOARD_READY
→ ASSETS_READY
→ AUDIO_READY
→ ANIMATIC_READY
→ MOTION_READY
→ EDIT_READY
→ QC_READY
→ HUMAN_APPROVED
→ PACKAGED
```

`PUBLISHED` 不由生产系统自动进入，只能由人工确认记录。

集级生产允许并行，但有三条依赖：角色和世界观圣经通过后才能批量写集；单集剧本通过后才能生成正式资产；animatic 通过后才能批量调用收费视频 Provider。

单集时长、画幅和结构全部配置化。当前竖屏试播默认 9:16、1080×1920、30 fps、60～90 秒；允许 30～180 秒。每集默认包含开场钩子、目标、阻碍、升级、转折/高潮和结尾钩子，但结构检查只提示问题，不机械改写故事。

## 6. Web 工作台

Web 端按真实制作流程分为十个工作区：

1. 项目总览：季度进度、待审核项、失败镜头、预算与成本。
2. IP 与底本：来源、版本、权利、章节索引和发布限制。
3. 故事圣经：世界观、人物、关系、地点、道具、时间线和伏笔。
4. 编剧室：全剧、季度、故事弧、单集大纲和剧本编辑。
5. 角色与美术：角色设定、服装、场景、道具、风格和资产版本。
6. 分镜台：场、镜头、构图、首尾帧、对白、时长和连续性对照。
7. 音频台：选角、逐句试听、对白、旁白、音乐、音效和混音。
8. 渲染队列：本地/远程路线、镜头状态、重试、成本和版本选择。
9. 审片台：animatic、动态成片、A/B 版本、问题批注和局部返工。
10. 发布包：封面、标题、简介、声明、导出和人工发布记录。

Web 端不是脚本按钮集合；所有编辑、审核和返工动作都作用于同一套项目数据与状态机。

Web 后端提供领域 API、媒体 API、任务 API 和审核 API。长时间图像、视频、配音与渲染任务进入持久化队列，浏览器只提交任务和订阅状态；刷新页面或重启服务不会丢失任务记录。密钥只通过环境变量、操作系统安全存储或当前会话注入，API 永不返回明文。

P18～P26 每个阶段都必须同时交付领域逻辑、API 和最小 Web 页面，不能先做一套 CLI 后再另写 Web。P27 的职责是导航、交互、批量操作、审片体验、备份恢复和全局状态整合。

## 7. Provider 与成本策略

Provider 分成能力而非品牌：

```text
LLM：解析、编剧、连续性检查
Image：角色、场景、道具、关键帧
Video：图生视频、首尾帧、文本生成
LipSync：口型
TTS：旁白与对白
Music/SFX：音乐和音效
ASR：成片复核
```

路由优先级由镜头需求决定。系统记录每次远程调用的预计成本和实际成本，设置项目、集和镜头三级预算。超过预算、未配置密钥、未通过 animatic 审核或未获得上传授权时，远程调用必须被拦截。

## 8. 新实施路线

### P18 架构与数据底座

- P18-01：定义 IP、Series、Season、Arc、Episode、Scene、Shot、Asset、Render Schema。
- P18-02：建立 SQLite Repository、JSON 快照、资产注册表、版本、依赖与变更影响图。
- P18-03：建立持久化作业队列、并发锁、重试、取消、状态机、审核门、局部重跑和迁移器。

### P19 IP 来源与故事知识库

- P19-01：底本、章节、来源定位和权利模型。
- P19-02：原文导入、章节切分、人物地点道具抽取。
- P19-03：世界观、角色、关系、时间线与连续性账本。

### P20 改编与编剧室

- P20-01：全剧和季度规划。
- P20-02：故事弧与单集卡片。
- P20-03：场景剧本、对白、旁白、原文映射与连续性 delta。
- P20-04：剧情审核和跨集矛盾检查。

### P21 视觉圣经与资产系统

- P21-01：风格、色彩和构图圣经。
- P21-02：角色设定、服装与身份一致性资产。
- P21-03：地点、道具和环境状态资产。
- P21-04：关键帧参考包、版本选择与资产审核。

### P22 分镜与 Animatic

- P22-01：Scene/Shot 分解、镜头语法和稳定 ID。
- P22-02：静态 storyboard 与首尾帧规划。
- P22-03：本地 animatic、临时配音和字幕。
- P22-04：节奏、可读性和连续性审核。

### P23 音频制作

- P23-01：角色选角与 voice profile。
- P23-02：逐句对白、旁白、情绪和发音版本。
- P23-03：音乐、环境声、音效与授权清单。
- P23-04：混音、响度和声画同步。

### P24 动态镜头

- P24-01：按镜头选择本地、图生视频、首尾帧、口型或人工导入。
- P24-02：Provider 队列、预算、上传授权、重试和回退。
- P24-03：镜头版本审核、角色一致性和动作可读性。

### P25 剪辑与后期

- P25-01：集级时间线、对白和镜头组装。
- P25-02：转场、特效、色彩、字幕和音频总线。
- P25-03：局部替换与无损重渲染。

### P26 六类 QC 与人工审核

- P26-01：来源权利、剧情和连续性 QC。
- P26-02：角色身份、画面、音频和技术 QC。
- P26-03：Web 批注、问题单、返工和版本对比。
- P26-04：人工确认、发布包和发布记录。

### P27 Web 制作台

- P27-01：项目、IP、故事圣经和编剧室。
- P27-02：角色资产、分镜和音频工作台。
- P27-03：渲染队列、成本、审片与问题单。
- P27-04：发布包、配置、备份和恢复。

### P28 《镜花缘》正式五集验收

- 迁移现有技术样片到新数据模型，不直接把旧文件当正式资产。
- 用新流程重新完成五集的连续剧情、角色视觉、配音、字幕和 animatic。
- 至少选择一集、三个代表镜头接入真实动作 Provider 做效果和成本对比。
- 通过六类 QC 和人工审片后，才决定是否扩展到第一季。

## 9. 第一阶段完成定义

P18～P22 完成后，系统必须能够：

- 创建一个小说 IP 项目并绑定底本与权利状态。
- 维护世界观、角色、关系和时间线。
- 规划一季、一个故事弧和至少五集。
- 从集纲生成场景剧本和逐镜分镜。
- 复用同一角色、场景和道具资产。
- 生成带临时配音、字幕和本地运镜的五集 animatic。
- 检测明显的跨集人物、服装、道具和时间线矛盾。
- 在 Web 中查看、编辑、审核和局部重做。
- 在未通过审核时阻止收费动作生成和发布。

后续动作模型、精细口型和高级特效建立在这套底座上，不反向定义故事数据。

## 10. 里程碑与非目标

```text
M1（P18～P20）故事可管理：能维护 IP、圣经、季度、故事弧和五集剧本
M2（P21～P22）样片可审核：能复用角色资产并产出五集连贯 animatic
M3（P23～P26）成片可生产：具备正式音频、动态镜头、后期、成本和六类 QC
M4（P27～P28）系统可使用：Web 制作台完整并通过《镜花缘》正式五集验收
```

本轮不提前建设多人协作、云端集群、全自动发布、模型训练或无限平台适配。先把单用户、本地优先、可恢复、可审核的连续剧生产系统做完整，再按真实瓶颈扩展。

每个阶段都需要 Schema/迁移测试、领域规则单元测试、Provider 合约测试和一条可恢复的端到端样例。涉及媒体输出时追加真实文件探测；涉及远程调用时使用模拟响应测试并保留显式付费确认；涉及发布时继续执行人工确认审计。
